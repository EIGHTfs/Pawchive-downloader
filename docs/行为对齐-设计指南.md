## 一、设计目标

对齐 Python 原版 KToolBox 的关键行为，修复以下问题（用户反馈 + 子代理研究归因）：

| # | 问题 | 对齐后行为 |
|---|------|-----------|
| 1 | 重复下载 `.tmp`（同作者多任务/多 cli 并发写同一文件） | 下载前 `.tmp` 检查 + **跨进程文件锁**（同 serverPath 只有一个下载） |
| 2 | 任务删除/取消后后台还在下载 | **abortCtl 真中断**（stop/pause/删除级联到下载器）；终态不被覆盖成 completed |
| 3 | 前端统计卡「已传输/预计剩余时间」无数据 | progressReducer **按 job 增量累计** transferred、total 有值、eta 计算、active 清理 |
| 4 | 断点续传中间丢失难发现 | **强校验模式**（默认关）：本地 sha256 vs serverPath 内容寻址 hash |
| 5 | 任务创建无去重 | 同作者已有 ACTIVE 任务 → **409 + current_task_id**（对齐原版 task_routes.py:73-77） |
| 6 | auto-sync 到期重复触发 + 全量拉取 | 触发前查重（同 creator ACTIVE 跳过） |

## 二、成功标准（已达成）

- 同作者建第二个 ACTIVE sync 任务 → 409（含 current_task_id）
- stop/pause/删除任务 → 下载真正中断 + 任务终态保持 stopped/paused
- 下载任务 progress：transferred_bytes 累计增长、total_bytes 有值、eta_seconds 计算、active_downloads 终态清理
- `PAWCHIVE_STRICT_VERIFY=1` → 本地 sha256 vs 目标 serverPath hash：**不符 → 优先修复（续传补齐/重校验）；修复不了 → 整文件重新下载**
- 跨 cli 同文件并发 → 只有一个下载（.tmp 检查 + 文件锁）
- 回归：webapi.test.js 26 项 + contract-check 19-20 端点 + 浏览器任务页

## 三、关键设计决策

### 3.1 任务创建去重（Step 3）

- **位置**：`adapters/KToolBox-webui.js` tasks POST（~491-518 行）
- **逻辑**：kind=sync 且同 `service+creator_id` 已有 **ACTIVE**（queued/blocked/running/pause_requested/stop_requested）任务 → 返回 **409** `{detail: '该作者已有任务在运行', current_task_id: <id>}`
- **边界**：任务已 completed/failed（非 ACTIVE）→ 允许再建（去重只拦 ACTIVE）
- **依据**：Python 原版任务创建双重去重（spec_json 精确查重 task_store.py:162-171 + 资源冲突 blocked task_scheduler.py:192-204 → 409+existing_task_id task_routes.py:73-77）
- **前端兼容**：前端已支持 409 模式（原版契约），无前端改动

### 3.2 任务真中断（Step 5）

- **链路**：`core.downloadTask` AbortController → `cli.downloadAuthor/downloadOnePost` worker → `downloadWithDedup` → `downloadFile` → `streamOnce` kill curl
- **abort 时保留 .tmp**（断点续传可恢复）；终态不被 completed 覆盖（用户 stopped/paused 保持）
- **abort 后 catch → interrupted 非 failed**（不虚高 failed_files；对齐原版 CancelledError）
- **adapter DELETE/stop 级联 abortTask**（core 导出）
- **依据**：Python 原版真中断（pause/stop 写状态 + running.task.cancel() 级联到下载器——stream.py:204-206 → downloader.py:325-327）

### 3.3 progressReducer 累计统计（Step 2）

- **transferred_bytes**：按 job 维度**增量累加**（lastSizes[fn] 基准——多文件并发 job.progress 交错不重复计数）
- **total_bytes**：jobTotals 累计和（job.progress totalSize）
- **speed_bps**：5s 滚动窗口均值（活跃 job 速度之和——单文件切换不归零）
- **eta_seconds**：`(total-transferred)/speed`，speed>0 时
- **active_downloads**：job 完成清理，条目含 creator_key/speed
- **2026-09-30 补漏**：无 size 记录文件（html 记录 size null → totalSize null → 未计入 jobTotals）下载完成时用实际 size 补进 total——transferred 不再超过 total

### 3.4 强校验模式（Step 4）

- **开关**：`PAWCHIVE_STRICT_VERIFY=1` **默认关**（sha256 大文件 CPU 开销）
- **流程**：下载完成 → 计算本地 sha256 vs 目标 `serverPath` hash（内容寻址天然可用）
- **不符 → 优先修复**：先尝试 .tmp 续传补齐到正确大小/重新校验——能修则修、不重下
- **修复不了 → 整文件重新下载**（重下兜底——不是"不重下"）
- **fsync（2026-09-29 对齐）**：续传前 `fs.open('r+') + fd.sync()`（防 OS 缓存 stat 与实际落盘不一致——空洞定位错）
- **200/206 显式处理**：续传时 `-D -` 输出响应头——200（服务器不支持 Range）→ .tmp 作废从头下（防旧数据+新数据拼接）
- **边界**：源站 API 不返回 hash / 目标路径非 sha 格式 → 跳过校验（不误判）

### 3.5 跨进程文件锁（Step 6）

- **位置**：`.pawchive/locks/<sha1(serverPath)>.lock`
- **机制**：`fs.open('wx')` **原子创建** + pid + mtime **24h 过期清理**（死锁）；downloadWithDedup 下载前拿锁（拿不到=别处 cli 在下→跳过 exists 防重复）；finally 释放
- **竞态**：多 cli 同时拿锁只有一个成功，其他跳过/等待（拿锁失败即跳过——不阻塞）
- **为何需要**（用户提问）：下载前检查只跳「已完成」——解决不了并发竞态（检查与下载非原子、hashIndex 进程内不共享、创建去重只防 WebUI 任务）——需跨进程机制

### 3.6 .tmp 分类处理（Step 1）

**不笼统清理 .tmp**（用户批评"清了还叫断点续传"后修正）——区分三类：

| 场景 | 处理 | 理由 |
|------|------|------|
| 下载中断的 .tmp（正式文件不存在） | **保留** | 断点续传基础（清了续传就断） |
| 冗余 .tmp（正式文件已存在 / 本次已由链接复用成功） | **清理** | 无续传价值（防堆积） |
| 下载前 .tmp 检查命中（别处在下） | **不清** | 破坏别处下载 |

- **下载前 .tmp 检查**：`savePath+tempSuffix` 存在（=别处正在下载该文件）→ 跳过/等待（不删别处 .tmp）
- **下载前 .tmp 检查命中（别处在下）→ 不清**（不破坏别处下载）

### 3.7 auto-sync 触发查重（Step 3 附带）

- triggerAutoSyncPlan 触发前——同 creator 已有 ACTIVE 任务 → **跳过不重复触发**
- checkpoint 增量窗口、调度器、rerun 真实重跑——**本次不做**，列后续优化（见第八节）

### 3.8 事件契约边界（2026-09-30 架构决策）

- cli.js 只发下载**自然事件**（job.*/download.*/post.* 带原始字段）——引擎全流程自含
- WebUI 契约字段（key/completed_bytes/total_bytes/elapsed_seconds/average_speed_bps/中文 message）由 **core.js onEvent 输出层合成**
- creator.started/finished 由 **core.js downloadTask 任务级**发（对齐原版 task_reporter webui 层发）
- 事件 data 统一补中文 message（EVENT_ZH/PHASE_ZH——前端事件流 fallback 显示）

## 七、讨论记录（设计决策来源——完整保留）

1. **下载前去重为何不能解决多 cli 并发**：检查与下载非原子、hashIndex 进程内不共享、创建去重只防 WebUI 任务——需跨进程机制（.tmp 检查 + 文件锁）
2. **强校验语义修正**：不符 → 优先修复（续传补齐）→ 修复不了 → 整文件重新下载——不是"不重下"
3. **前端统计卡反馈**：总下载速度/已传输/文件/预计剩余时间——已派子代理全面检查前端数据获取
4. **重复下载 .tmp 不是个例 + 任务删除后还在下载**：添加同步任务应按作者去重（原版 409+existing_task_id）
5. **推送授权**：本地提交可推送——GitHub API push 403——SSH 通道处理
6. **.tmp 分类修正**（批评"清了还叫断点续传"）：保留下载中断 .tmp / 只清冗余 .tmp / 下载前命中不清
7. **P1 决策**：①搜索补字段 ②任务编辑方案 A ③MCP 空对齐 ④四方案 + P1 全部实施
