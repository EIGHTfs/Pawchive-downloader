## 结论摘要

- **✅ 一致/合理**：真中断方向（.tmp 保留 + 终态保持）、.tmp 分类（续传保留 + 冗余清理增强）、跨进程文件锁（独有增强不破坏语义）、强校验（独有增强默认关）、MCP 空对齐、schedule kind 补全。
- **⚠️ 语义差异（建议修）**：
  1. **total_bytes = max 非累计和**（`core.js:263`）——统计卡「总数」偏小，应累计任务已知文件 total 之和（对齐 `task_reporter.py:125-129`）。
  2. **abort 后剩余文件计 failed 虚高**（`cli.js:782` failed:aborted → job.failed）——建议 abort 时任务级短路（不再逐文件标记失败）。
  3. **任务创建去重范围/字段**：download 任务未去重；409 字段名 current_task_id vs existing_task_id；sync 按作者宽松匹配。
  4. **事件类型未对齐**：缺 download.started/retrying/finished（前端 transfers 视图/消息模板消费）、task.status 无 progress 快照（SSE 进度不实时）——且不在后续清单。
  5. **P1-2 编辑范围**：queued/blocked 拒改（原版可改）；缺编辑后 spec 查重。
  6. **P2-1 raw 保存 content 被忽略**（只处理 values）——保存显示成功但 .env 未更新。
- **❌ 本次实施引入的回归 bug（建议立即修）**：
  1. **P1-1 user 字段类型错**：返回 `{id,name}` 对象 vs 契约 string → 详情/建任务断链（`KToolBox-webui.js:342`）。
  2. **P2-2 directories 参数读取错**：读 query 不读 body → 新建/删除文件夹与前端交互失效（`KToolBox-webui.js:507-522`）。
