## 任务页统计卡专项（用户反馈）

任务详情页（TasksPage 内 TaskDetails）顶部四个 Metric（`pages/TasksPage.tsx:911-916`）：

| 统计项 | 前端读的字段（源码:行） | 我们响应（位置） | 状态 | 影响（显示什么） |
|---|---|---|---|---|
| 总下载速度 | `progress.speed_bps`（`lib/taskMetrics.ts:10`，经 `taskDownloadSpeed`；TaskDetails 912 行 + TaskList 顶部总速度 512/579 + DashboardPage 75 行） | `core.js:257` 直接覆盖 `d.speed`（单文件瞬时速度，非总速度） | 错 | 显示当前**最后一个文件**的瞬时速度而非任务总速度；并发时数值偏小/跳动；`speedStatuses` 只认 running/pause_requested/stop_requested（Node 停止后变 stopped → 显示 0） |
| 已传输 | `progress.transferred_bytes` + `progress.total_bytes`（`TasksPage.tsx:913`） | `core.js:256` `Math.max(prev, d.size)`（**非累计**，取当前最大单文件已写字节）；`core.js:249` total_bytes 恒 null（无 case 更新） | 错 | 已传输显示**远小于真实累计值**；总字节 `formatBytes(null)` → **"—"**（`lib/format.ts:3-4`）→ 卡片显示「1.2 MiB / —」 |
| 文件 | `progress.processed_files` / `progress.queued_files`（`TasksPage.tsx:914`，进度条 786 行同款） | `core.js:260-263` job.queued/downloaded/existed/failed 递增 | 有 | 正常显示（该两项已对齐） |
| 预计剩余时间 | `progress.eta_seconds`（`TasksPage.tsx:915`，`formatDuration`） | `core.js:249` 恒 null（无计算） | 缺 | `formatDuration(null)` → **"—"**（`lib/format.ts:20-21`）→ 卡片永远显示破折号 |

**配套显示点**：
- 任务进度百分比（`TasksPage.tsx:792-800` `taskDisplayPercent` → `lib/format.ts:45-48` `taskPercent`）：Node total_bytes=null 时走 `processed/queued` 分支（可看），但若 total_bytes 有值会走 `transferred/total` → 因 transferred 非累计而严重偏小。当前 Node 恒 null 反而「凑巧」走到文件数分支。
- 任务详情顶部 `ProgressMeter`（`TasksPage.tsx:910`）：`isIndeterminate = discovering || (running && !total_bytes && !queued_files)`——Node 总字节 null 时，若 queued_files=0（全跳过帖）进度条转无限动画。
- 任务详情 active_downloads 面板（`TasksPage.tsx:947-957`）：前端读 `download.creator_key`（954）与 `download.speed_bps`（955）——Node `core.js:258` 存的是 `{filename, percent, speed, size}`（**无 creator_key、无 speed_bps**）→ 创作者显示空、速度显示 "—"；且 job.downloaded/job.existed/job.failed **不清除** active_downloads（`core.js:258` vs `261-263`）→ 任务完成后面板残留旧条目。

## 缺失/错误汇总（按影响排序）

**P1（用户可感知功能不可用/链路断裂）**
1. **PostsPage 搜索链路断裂**：/pawchive/posts 列表项缺 `service`/`user`（`KToolBox-webui.js:323-324`）→ 详情请求 404、创建下载任务 400；且 `name/query/offset` 参数被忽略（只按 creator_id+service 拉前 100 帖）。用户反馈的「posts 搜索用不了」即此。
2. **任务编辑失效**：PATCH /tasks/{id} 忽略 body.spec（`KToolBox-webui.js:526`）→ 编辑任务保存无效（200 但没改）。
3. **任务统计卡四项中三项失真**（用户反馈核心）：transferred_bytes 非累计（`core.js:256`）→ 已传输偏小；total_bytes/eta_seconds 恒 null（`core.js:249`）→ 显示 "—"；speed_bps 单文件瞬时 → 总速度偏小。文件数两项正常。
4. **MCP 页面数据全 404**（`KToolBox-webui.js:560-561`）：/mcp/status、/mcp/tokens、/mcp/tools 无端点 → 页面「不可用」+ 0 工具（设计移除，但页面仍可路由进入）。

**P2（行为不对/数据缺失）**
5. **ConfigurationPage raw 保存/校验不可用**：PUT /config/dotenv/{name}、PUT /config/project、validate、/config/example 均无端点（adapter 只实现 GET+PATCH /config/dotenv）。
6. **RemotePathField 新建/删除文件夹 404**：POST/DELETE /filesystem/directories 未实现。
7. **AutomaticSync 计划解析错位**：Node schedule 无 kind → 前端按 cron 解析（默认「0 3 * * * · UTC」）；options 字段缺失 → 保存后丢失。
8. **任务详情 active_downloads 字段错**：Node 条目 `{filename,percent,speed,size}` vs 前端读 `creator_key`/`speed_bps`（`TasksPage.tsx:954-955`）→ 创作者空、速度 "—"；完成不清理 → 残留。
9. **任务事件日志错位**：job.progress 500ms 刷屏 + Node 事件类型不在前端 activity/transfers 过滤与消息模板覆盖内（`lib/taskFailures.ts:108-200`）→ 日志内容错乱、无字节/时长信息。
10. **SSE 实时进度不更新**：Node 事件不在前端 EventSource 监听表（`lib/realtime.tsx:56-94`）、task.progress 无 progress 快照 → 任务列表进度只靠轮询刷新，实时感缺失。
11. **任务标题缺真实标题**：创建任务不存 presentation（`KToolBox-webui.js:514`）→ TaskTarget 显示「帖子 #id」。

**P3（轻微/可接受）**
12. SystemPage project_config 恒 ''、dotenv_files []（`KToolBox-webui.js:143`）→ 空行显示。
13. /config/project 缺 name 字段（TextDocument.name）→ 编辑器 raw tab 无名称（不崩）。
14. PostsPage 详情缺 cover/media/时区字段 → 图廊/封面/时区文案空。
15. Blockers 页空对齐（保存恒 200 空）——功能被模拟关闭，符合「空对齐」设计。
16. auto-sync run 恒 200 无 409 → 前端 conflict 分支不触发（与行为研究第一轮结论一致）。
17. ExternalChangeAlert 永不显示：Node 不发布 naming.changed/configuration.changed/blockers.changed 等事件（`lib/realtime.tsx:477-511` 依赖）→ revisions 恒 0（合理降级）。
