## 一、P0——功能错误/数据错乱（需立即修）

### 1. finishAttempt 硬编码 sequence=1（resume/stop 重跑后 attempt 记录错乱）
- **代码证据**：core.js:445/471/477 `finishAttempt(taskId, 1, ...)` 三处硬编码 `1`；而 startAttempt（core.js:248-253）已改为 MAX+1 自增（bc37113）。
- **断链**：任务 stop/pause→resume（或失败后重跑）→ 调度器再次 downloadTask → startAttempt 创建 **sequence=2** 的新 attempt → 完成/失败/中断时 finishAttempt(taskId, **1**) **更新的是旧 attempt 1**，新 attempt 2 永远停留 running。
- **影响**：task_attempts 记录错乱（旧被覆写、新恒 running）；listAttempts（前端 attempts 视图）显示错误；重跑统计失真。
- **修复方向**：startAttempt 返回新 sequence，downloadTask 记录 `curSeq`，finishAttempt 用 curSeq。

### 2. scheduleTick 启动只传 4 字段——syncLength/save_creator_indices/offset/keywords 全丢
- **代码证据**：core.js:598 `downloadTask(t.id, { service, creator_id, post_id, url }, targetPath, { concurrency: schedulerMaxActive, dryrun: !!spec.dryrun })` —— 只传 4 个核心字段；且 **downloadTask 唯一调用点就是这里**（全仓 grep 仅 core.js:598，server.js 只启调度器，adapter 创建任务后调 scheduleTick）。
- **断链 2a（auto-sync 增量彻底失效）**：triggerAutoSyncPlan 建任务 spec 含 syncLength（core.js:624），但调度器启动不传 → downloadTask 内 `spec.syncLength ? { length } : {}`（core.js:430）永远 undefined → **每次全量拉取**；checkpoint 更新 `if (spec.syncLength ...)`（core.js:454）永不执行 → **last_checkpoint 永不更新**。
- **断链 2b（两开关 save_creator_indices/download_file 双层丢失）**：adapter :589 建 spec 已丢弃两字段（之前调查确认）+ 调度器启动再丢一层 → 原版真实生效（action/job.py:120-121/272/292-294），我们完全失效。
- **断链 2c**：concurrency 用 schedulerMaxActive（全局值）而非 spec 配置。
- **修复方向**：scheduleTick 把完整 spec 透传给 downloadTask（`downloadTask(t.id, { ...spec, url }, ...)`）。

### 3. 前端活动视图过滤掉全部 download.retrying 事件（compactActivityEvents 无 key）
- **代码证据**：docs/.probe-ktoolbox/webui/src/lib/taskFailures.ts compactActivityEvents：`const key = typeof event.data.key === "string" ? ... : ""; if (!key || latestRetries.has(key)) return false;` —— **key 空 → return false → 全部重试事件被过滤**。
- **我们侧**：cli.js:1647/1797 download.retrying 只发 `{ filename, retry_count }`，**缺 key 字段**。
- **影响**：前端活动/transfer 视图永远看不到重试记录（事件流有、视图过滤掉）。
- **修复方向**：cli 发 `key: job.filename`（或 filename 本身）。

## 二、P1——面板/事件模板断链

### 4. waiting_retries 恒空（progressReducer 无 download.retrying case）
- **代码证据**：core.js:348 初始 `waiting_retries: {}`，**无任何 case 填充/清除**；cli 已发 download.retrying（cli.js:1647/1797）但聚合层不消费。原版 task_reporter.py:165-194 填 / :130/:214 pop。
- **修复**：progressReducer 加 download.retrying case（`waiting_retries[filename] = { creator_key, filename, retry_count, status_code }`）；job.downloaded/existed/failed/aborted 时 pop。

### 5. active_creators 恒空（cli 不发 creator.* + 无 case）
- **代码证据**：cli.js grep 无 `creator.started/creator.finished` emit；core.js:348 初始 `active_creators: []` 无 case。原版 task_reporter.py:70-101 append/remove；前端 taskFailures.ts:146/166 有 creator.finished/creator.started 模板分支（事件缺失 → 模板永不触发）。
- **修复**：cli downloadAuthor 开始/结束发 creator.started/finished（data 带 creator/fetched_posts/accepted_posts/queued/completed/existing/failed——对齐前端模板字段）；progressReducer case append/remove。

### 6. 前端事件模板字段缺失（download.* 三兄弟走专门模板、message 补丁不生效）
- **代码证据**：taskFailures.ts eventMessage 顺序 = parseFailureReport → parseFailureItem → **download.retrying**（:140）→ **creator.finished**（:146）→ **download.started**（:166）→ **download.finished**（:177）→ message fallback（:191）——**download.* 在 message fallback 之前**，我们的 EVENT_ZH message 补丁（core.js:418-419）对这仨不生效。
- **字段缺口**：
  - download.started（cli.js:1639 只发 filename/creator）模板需 `completed`/`total`（formatBytes(undefined) → 显示空）
  - download.finished（cli.js:1656 只发 filename/outcome/status/size）模板需 `completed_bytes`/`total_bytes`/`elapsed_seconds`/`average_speed_bps`（4 字段全缺 → 空值）
  - download.retrying（cli.js:1647 只发 filename/retry_count）模板需 `status_code`（显示 "HTTP —"）
- **修复**：cli emit 时补全模板所需字段（started: completed/total；finished: completed_bytes/total_bytes/elapsed_seconds/average_speed_bps；retrying: status_code）。

## 三、P2——对齐瑕疵/低影响

### 8. post.skipped / revision.completed / netdisk.downloaded / task.started 无聚合 case
- progressReducer 仅 post.completed 有 case（core.js:384-391，带 hasJobs 防双计 ✓）。

- revision.completed（cli.js:1663）、netdisk.downloaded（cli.js:1830）、task.started（cli.js:1861）：事件流冗余，进度已在 job.* 聚合——可接受。

### 9. 前端 eventTypes 不含 job.progress/job.downloaded/job.existed/job.failed/job.aborted/post.*
- realtime.tsx:56-94 eventTypes 只含 task.*/download.*/creator.*/job.queued/配置类——job.*（除 queued）和 post.* 不在监听表。
- **非断链**：P2-5 已通过 task.status/task.progress 内嵌 progress 快照传递进度（core.js:230/418/427）→ 前端实时更新 ✓。job.* 事件仅落库供 /events 查询。
