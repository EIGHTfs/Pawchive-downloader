# 源站资源删除（404）场景：行为结论

> 日期：2026-09-28 ｜ 实测案例：`https://pawchive.pw/patreon/user/59949475/post/p-693325`（Akt「【2024 S1】 Spring 春」帖，11 文件）

## 一、实测结果

```
[已存在] 芙宁娜 Furina.mp4 ...（共 8 个本地已有文件）
[失败(failed:curl_exit_22)] 花火 Sparkle S.mp4 / 流萤 Firefly S.mp4 / 阮梅 Ruanmei S.mp4（本地缺失 3 个）
[DOWNLOAD] 完成: 新下载 0 / 已存在 8 / 快速跳过 0 帖 / 失败 3
```

## 二、行为结论

| 场景 | 行为 | 正确性 |
|---|---|---|
| **本地已有 + 源站 404**（网站删了资源） | `[已存在]` 跳过——**不重下、不删除本地文件** | ✅ 本地资产安全 |
| **本地没有 + 源站 404** | `curl -f` 拦截 → 一次性失败（不落 404 页、不重试、计入失败清单并列出路径） | ✅ 明确报缺失 |
| 失败文件统计 | 完成行列出完整路径（`Akt/【2024 S1】 Spring 春/...`） | ✅ 可人工核对 |

## 三、实现机制

1. **本地已有文件保护**：下载前「大小感知检查」——目标文件存在且大小与 html 记录一致 → `exists` 跳过（不触发下载、不触碰源站）；即使源站已 404，本地文件原封不动
2. **源站 404 拦截**：curl 带 `-f`（HTTP 4xx/5xx 直接失败 exit 22），`curl_exit_22` 为确定性失败**不重试**、不落 404 页面、不产生 `.tmp` 残留
3. **缺失文件明确报错**：失败文件计入完成统计（路径列全），供人工判断（源站已删则永久缺失，可手动补回后重跑自动识别为已存在）

## 四、意义

- 「网站没了资源、本地已有」= 本地资产**永不因源站删除而丢失/重下**（离线归档安全）
- 仅「本地也缺失」的文件报失败——提示源站删除造成的真实缺口，可人工补档
