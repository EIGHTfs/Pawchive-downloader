# 协议切换兼容层 — 设计文档

> 状态：**已实施（2026-09-29）**——全部端点落地、功能完成（本文档含设计过程记录供追溯）｜ 目标：KToolBox 前端直接接我们 Node 后端（API 中间兼容层——不改前端源码/bundle，按契约实现），且协议层可插拔切换

## 一、目标

- KToolBox 前端（webui/src 源码可读；webui-static bundle 为构建产物，兼容层不改动）→ 我们的 Node 后端（API 中间兼容层）——前端零改动可用
- **协议可切换**：兼容层按「协议适配器」分层——接 KToolBox 契约是当前目标，未来自研前端用 native 协议只加适配器，业务内核不动
- 范围（用户已确认收窄）：**无登录认证（session 三端点放行已登录）、无 MCP（404 删除）、naming=命名模板映射、config schema 26 字段**

## 二、架构总览

```
浏览器（KToolBox 前端——webui-static bundle，兼容层不改动；契约源=源码+openapi.yaml）
   │  GET /（SPA 静态） + /api/v1/*（契约端点）
   ▼
server.js ── HTTP 服务（零依赖 node:http）
   ├─ 静态托管：webui-static/（自 docs/.probe-ktoolbox/ktoolbox/webui/static 复制入库）
   ├─ 协议注册表 PROTOCOLS = { 'KToolBox-webui': <adapter>, 'native': null（预留——adapter 未建） }
   │    （PAWCHIVE_WEB_PROTOCOL env 选择；默认 KToolBox-webui；切换协议 = 换适配器）
   └─ 路由分发 → 协议适配器 → 业务内核（core）
        adapters/KToolBox-webui.js  KToolBox 契约翻译（收窄端点）
                     ↓
        core.js ── 业务内核（协议无关，复用 cli.js 能力）
        ├─ 任务模型（10 态状态机 + attempts + SQLite 持久化）
        ├─ 创作者/文件浏览（pawchive-index 双级索引读）
        ├─ 下载执行（内嵌 cli downloadAuthor + 进度事件）
        └─ 配置（PAWCHIVE_* 读写）
```

## 三、分层职责

| 层 | 职责 | 依赖 |
|---|---|---|
| `server.js` | HTTP 服务、静态托管、路由分发、协议选择、SSE 通道、①层 error-reporter 注入、DEBUG 启动自检、auto-sync 调度器启动 | node:http 零依赖 |
| 协议适配器 | 「KToolBox/native 请求解析 → core 调用 → 组对应协议响应结构」——**只翻译，无业务**（filesystem 浏览/配置 schema 等小逻辑内联于 adapter） | core |
| `core.js` 业务内核 | 任务/创作者/文件/配置/下载执行/auto-sync 计划——**协议无关，单一实现** | cli.js（复用 downloadAuthor/索引/CONFIG） |

## 四、协议注册表与切换

```js
// server.js
const PROTOCOLS = {
  'KToolBox-webui': require('./adapters/KToolBox-webui.js'),
  'native': null, // 预留：未来自研前端（adapter 文件未建）
};
const protocol = PROTOCOLS[process.env.PAWCHIVE_WEB_PROTOCOL || 'KToolBox-webui'];
// 请求 → protocol.handle(method, path, req, res) → core
```

- 切换协议 = 改 `PAWCHIVE_WEB_PROTOCOL`（或 URL 前缀路由：`/api/v1/*` → KToolBox 适配器）
- 契约变化（KToolBox 升级）只改对应适配器；core 不动

### 任务模型 + 事件对齐原作者（已实施）

**存储**：SQLite（node:sqlite 对齐）——`tasks(id,kind,status,spec_json,presentation_json,position,revision,progress_json,error,failure_json,created_at,updated_at)` + `task_attempts(id,task_id,sequence,status,spec_json,configuration_json,started_at,finished_at,error,failure_json,result_json)` + `task_events(id AUTOINCREMENT,task_id,event_type,resource,resource_id,data_json,created_at)`；WAL 模式

**任务状态机（10 态）**：queued/blocked/running/pause_requested/paused/stop_requested/stopped/completed/failed/interrupted；ACTIVE={queued,blocked,running,pause_requested,stop_requested}；TERMINAL={paused,stopped,completed,failed,interrupted}

**执行**：内嵌 cli `fetchPostsByUrl + downloadAuthor`（原 JobRunner 等价）+ `onEvent` 回调（原 reporter）→ 写 task_events + 推 SSE；`progressReducer` 聚合 TaskProgress（queued_files 对齐原版 job_queued 累计）

**事件类型（cli 实际发出）**：`task.started` / `post.started` / `job.queued` / `job.progress` / `job.downloaded|existed|failed` / `netdisk.downloaded` / `post.completed` / `post.skipped` / `task.completed` / `revision.completed`；core 自 publish `task.progress`（phase: started/resume/pause/completed/failed）

**SSE**：`/api/v1/events`：`Last-Event-ID`/`?after=` cursor → 查库补发 → Condition 等待 → `id: N\nevent: type\ndata: {json}\n\n` 增量 + 15s `event: heartbeat`

### config 三端点（26 字段 6 分类——已落定）
